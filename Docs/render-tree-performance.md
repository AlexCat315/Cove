# 渲染树性能优化

2026-10-29，输入为 `cove-timeline(1).json`。225 次 `Encode draw list` 的平均耗时为 11.20 ms，P95 为 26.74 ms，峰值为 82.57 ms。辅助功能快照平均为 2.27 ms；另有一次 268.72 ms 的重组和一次 40.16 ms 的 Yoga 布局峰值。

渲染树现在缓存按 zIndex 排序的节点数组、父索引和子树结束位置。结构或 zIndex 变化时重建；每帧按父索引累计变换，纯结构节点无需建立绘制记录，缓存命中和离屏裁剪直接跳过整段子树。显式退出记录保留遮罩、透明度、overlay 和缓存提交的原有顺序。节点脏标记、资源卸载、渲染镜像和帧末清理也移除了递归。

顶点平移、索引重定位、透明度和边界扫描由优化编译的 C 内核执行。在多核宿主上，前三项在至少有两个 16,384 元素区间时并行执行，最多使用八个 worker；所有任务在数组借用结束前同步完成。绘制回调与场景对象继续由 UI 线程管理。macOS、iOS、Linux、Windows、Android 共用此实现；单线程 WASI 使用相同 C 内核串行执行。

缓存叶子平移时，只有在父裁剪未变化、没有局部裁剪、缩放未变化，且原始边界没有被圆角切割、平移后也不触及圆角时，才跳过重复的三角形裁剪。进入圆角或改变缩放时重新录制。

## 固定滚动基准

Apple M1，1,200 行，每行一个结构容器和一个绘制八个矩形的叶子。视口为 1,200 × 800，每帧滚动 7 pt，预热 30 帧，统计后续 60 帧。以下为编译结束后单独测量的结果；每种配置在同一进程中运行旧递归遍历与新扁平遍历。两者使用相同的新版 C 几何内核，隔离遍历和裁剪复用的差异。

| 配置 | 场景 | 旧遍历 P50 / P95 | 扁平遍历 P50 / P95 | P50 降低 |
| --- | --- | --- | --- | --- |
| Debug | 矩形裁剪 | 2.257 / 2.299 ms | 1.819 / 1.876 ms | 19.4% |
| Debug | 16 pt 圆角裁剪 | 3.189 / 3.296 ms | 2.617 / 2.734 ms | 18.0% |
| Release | 矩形裁剪 | 0.448 / 0.539 ms | 0.425 / 0.532 ms | 5.1% |
| Release | 16 pt 圆角裁剪 | 0.497 / 0.566 ms | 0.468 / 0.565 ms | 5.7% |

这些是合成场景的 CPU 绘制列表耗时，不能直接替代附件中 Gallery 的帧耗时。重组、Yoga 布局调度和原生辅助功能快照仍是独立的优化方向。当前实机验证为 macOS；其他平台共用代码，但未执行目标设备验证。

运行回归和当前实现的基准：

```sh
COVE_SDK_ROOT="$PWD" cove test Core --no-parallel
COVE_SDK_ROOT="$PWD" cove test Tests/Headless --no-parallel
COVE_SDK_ROOT="$PWD" COVE_RENDER_BENCHMARK=1 cove test Tests/Headless --no-parallel --filter RenderPipelinePerformanceTests
```
