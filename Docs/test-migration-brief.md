# Rust test-migration brief

Shared context for every worker migrating Cove's remaining Swift tests to Rust.
Read this fully before writing code.

## Goal

Port every Swift test file in your assigned group to a Rust integration test in
the owning crate, behaviour-for-behaviour. No empty tests, no `#[ignore]`, no
`todo!()`, no silently dropped assertions.

The tracking manifest (`Docs/rust-migration-files.json`) is regenerated by
`Tools/Migration/inventory.py`, which matches a Swift test to a Rust **test
target name** (the `[[test]] name` value), not a file path. Use the target name
given in your group list exactly — it is the source stem in snake_case.

## Recipe (proven, follow it exactly)

1. Read the Swift test. List each `@Test` case and its assertions.
2. Write `<crate>/rust/tests/<target_name>.rs`.
3. Register it (serialized, idempotent — safe under parallel workers):
   ```
   ./Tools/Migration/register_test.py <CrateDir> <target_name>
   ```
   `<CrateDir>` is the crate directory name (`Compose`, `Core`, `Graphics`,
   `Examples`, `Terminal`, `Hosts`, `Logging`, `Text`, `Sources`, `Runtime`,
   `DevTools`). The script refuses to register a missing file.
4. Verify it compiles **and passes**:
   ```
   cargo test -p <crate-package> --test <target_name>
   ```
   Package names: Compose=`cove-ui-compose`, Core=`cove-core`,
   Graphics=`cove-graphics`, Examples=`cove-examples`, Terminal=`cove-terminal`,
   Hosts=`cove-hosts`, Logging=`cove-logging`, Text=`cove-text`,
   Sources=`cove-ui-addons`, Runtime=`cove-runtime`, DevTools=`cove-devtools`.
5. Iterate until it passes. A test that does not pass is not migrated.

## Test file shape

Match the existing convention (see `Compose/rust/tests/zstack.rs` or
`Compose/rust/tests/row_slot.rs`):

```rust
//! Translation of `Tests/CoveUIComposeTests/SomethingTests.swift`.
//!
//! Behaviour checklist:
//! - first behaviour the Swift suite asserted
//! - second behaviour

mod support;            // Compose only, when using the shared harness

use ...;
```

Use `#[test]` functions. Assert with `assert!`, `assert_eq!`, and descriptive
messages carrying the actual value. Do not add comments inside test bodies
unless the logic is genuinely non-obvious.

## Compose tests: use the shared harness

`Compose/rust/tests/support/mod.rs` provides `InteractiveScene`, a direct port of
`Tests/CoveUIComposeTests/InteractiveScene.swift`:

```rust
use support::InteractiveScene;

#[test]
fn some_case() {
    InteractiveScene::run(800.0, 600.0, |scene| {
        scene.install(some_view);
        let node = scene.named("debug-name").expect("mounted");
        scene.click(&node, 1);
        scene.key(scancode, KeyModifiers::LEFT_GUI);
    });
}
```

Available: `install`, `settle(ticks, delta)`, `dispatcher()`, `nodes()`,
`first(pred)`, `all(pred)`, `labelled(label, role)`, `named(name)`,
`click(&node, clicks)`, `click_at_point(point, clicks)`, `drag(start, end, steps)`,
`key(scancode, modifiers)`. It installs private interaction/focus/capture/portal/
text holders and restores them on exit — never install those holders yourself
inside a Compose test.

For tests that do not dispatch input, `GlobalTestLock::locked(|| { .. })` and
`support::with_test_text_environment(|| { .. })` are also available, and `graph()`
builds a bare `ViewGraph`.

Swift→Rust name mapping already applied in this repo (use the Rust names):
`XCTAssertEqual`→`assert_eq!`, `#expect`→`assert!`, `try #require`→`.expect(..)`,
`CGPoint`→`Point`, `CGSize`→`Size`, `CGRect`→`Rect`, `absoluteFrame`→
`absolute_frame()`, `KeyModifiers.gui`→`KeyModifiers::LEFT_GUI`, `attachments[Key]`→
`node.attachment::<T>(Key)`, `accessibility?.label`→
`node.accessibility()` returns `Option<AccessibilitySemantics>` (a value, not a
pointer).

Swift `.serialized` suites map to ordinary `#[test]`s because the harness already
serializes through a process-wide mutex.

## Rules

- **Never edit shared files owned by other workers**: the crate `Cargo.toml`
  (use `register_test.py` instead), `Compose/rust/tests/support/mod.rs`,
  `Docs/rust-migration*.{md,json}`, `CHANGELOG.md`, root `Cargo.toml`.
- **Never edit production Rust** unless a genuine defect blocks migration. If you
  find one, report it in your final message instead of fixing it silently — the
  Lead coordinates production changes.
- Do not weaken an assertion to make a test pass. If the Rust production code
  genuinely lacks a capability, delete nothing: port what exists, and record the
  gap explicitly in the module doc comment as a named difference plus a
  `#[test]` asserting the current, documented behaviour, or report it.
- Do not create new crates or parallel module trees.
- Tests must pass on this machine (macOS/arm64). Gate genuinely
  platform-specific tests with `#[cfg(target_os = "...")]` rather than deleting
  them — but do not gate something that would pass here.
- Keep one test target per Swift suite. Do not merge several Swift suites into
  one target; the manifest matches on target name.

## Reporting

When you finish, reply with:
- the target names you migrated and their pass/fail status,
- any production gap you found (file, symptom) — do not fix it yourself,
- any Swift file you judged to be a support file rather than a suite, and which
  Rust support module covers it.
